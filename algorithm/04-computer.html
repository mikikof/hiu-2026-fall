DEMO · プログラム格納方式

CPU は、番地の順に 3 拍をくり返す

プログラムカウンタが指す番地から命令を 取り出し、命令解読器が 解読 し、そして 実行 します。「次へ」で 1 拍ずつ進みます。

空欄①〜⑦をタップすると答えが表示されます。④⑤⑥ の 3 語 が、この単元の骨組みです。

コンピュータに動作を指示する命令を組み合わせて、処理の手順が記述されたものを（①）という。動作の指示を CPU が直接理解できる命令は、（②）と呼ばれるが、これは人にとって扱いづらい。そこで、人にとってわかりやすい単語や記号を使って、（①）を作成できる（③）が人の手によっていくつも考案されている。

解答は ① エ、② イ、③ ウ、④ ア、⑤ オ です。SUB 命令はレジスタから主記憶装置の値を引く命令なので、（Y ＋ Z）の答えを一旦 13 番地に格納してから X を読み込みます。

SUPPLEMENT · 式と手順

同じ答えでも、手順の数は変わる

X −（Y ＋ Z）は X − Y − Z と同じです。式を展開すると、途中結果を書き出す必要がなくなります。

もとの順

先に括弧の中を計算する

（Y ＋ Z）を先に計算するので、その答えを置く場所が要ります。STOP を除く命令は 6 つです。

展開した順

左から順に引いていく

X から Y を引き、続けて Z を引きます。レジスタの中身を捨てる場面がないので、書き出しは最後の 1 回だけ。STOP を除く命令は 4 つです。

EXTRA 1 / スタック

呼び出しの戻り先を積む

A が B を呼び、B が C を呼ぶと、C → B → A の順に戻ります。多くのコンピュータでは、終わったあとに戻る番地をスタック（stack）に積みます。

前半の「積む山」

最後に積んだものから取り出します。
ここでは、盾の代わりに戻り先の番地を積みます。

A → B → C

EXTRA 2 / 上限

積みすぎると溢れる

終わりの条件がないまま呼び出しを重ねると、戻り先を積み続けます。積める場所には限りがあります。上限に当たると、処理を続けられません。

呼ぶたびに積みます

呼び出しが終わらず、その先を呼び続けると、戻り先が増え続けます。

山にも上限があります

上限を超えて積もうとすることをスタックオーバーフロー（stack overflow）といいます。

Python では例外で止めます

呼び出しの深さの上限は既定で 1000 です。超えると RecursionError が出ます。

終わりの条件と戻り道は、第7回「再帰」で、もう一度扱います。

補足 · Python の実測値

2026-10-14、Python 3.13 の sys.getrecursionlimit() は 1000 でした。上限を超える呼び出しで RecursionError: maximum recursion depth exceeded を確認しました。1000 は呼び出しの深さの上限の設定値です。

EXTRA 3 / キュー

印刷の順番待ち（身近な実物）

1 台のプリンターへ届いた文書は、届いた順に並び、前から印刷されます。これがキュー（queue）です。Windows では「印刷キュー」という窓で、待っている文書の一覧を見られます。
